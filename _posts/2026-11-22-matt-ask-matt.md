## 英文原文
{: #original}

这一课讲 Matt Pocock 的技能 `ask-matt`。官方说明页是 <https://www.aihero.dev/skills-ask-matt>。官方技能文件是 <https://github.com/mattpocock/skills/blob/main/skills/engineering/ask-matt/SKILL.md>。第 1 课在旧站，本站不转载。本课是本站的第 2 课。

未获准全文转载。每个来源只摘不超过 25 个英文词，其余用我的话说明。

说明页的短摘：

> It recommends and stops. It does not grill, write a spec, open a file or fire the skill it just named

技能文件的短摘：

> You don't remember every skill, so ask.

官方目录的顺序，以 AI Hero 技能页列出的链接为准：Getting Started 里先是 setup，接着就是本课；下一项是 Main Flow 开头的 grill-with-docs。见 <https://www.aihero.dev/skills>。这和已经约定的早期顺序一致，本课不改道。

## 中文翻译与讲解
{: #explain}

先译短摘。说明页那句的意思是：它给出建议，然后停住。它不进行追问，不写规格，不打开文件，也不去启动它刚刚点名的那项技能。技能文件那句的意思是：你记不住每一项技能，所以去问。

作者的说法是：这是一张手写的地图，覆盖的是这一个仓库里被推荐的技能，不是扫描你机器上已经安装的全部技能。因此它不会把你自己写的技能，或别人作者的技能，排进路线。我的理解：把它当成「这套技能的问路处」，不要把它当成「我电脑上所有技能的索引」。

不用它，会卡在这里：技能已经有一串名字，你面对一个还没说清的想法，或者一堆别人交来的问题，却不知道第一步该敲哪一项。最常见的岔路是直接说「帮我把功能做了」。代理于是开始改文件。另一条岔路是两样技能看起来都能用，你凭感觉挑一个。说明页认为，这种时候该问的是路线，不是立刻开工。

按作者写在说明页上的用法，做这四步：

1. 你自己输入 `/ask-matt`。说明页写明，要由你来调用，代理不会自己去拿它。输入是你的处境，不是一份已经写好的规格。
2. 路由器把你放上一条路线里的某一步。作者把路线叫做 flow，意思是穿过多项技能的一条路径，不是「哪个词最像你的问题」。
3. 它返回下一条该敲的命令，并指出这条路上哪里要人来做决定，例如哪里该清空上下文、哪里该压缩上下文、哪里要你复查。返回的是「下一句你要自己敲的字」。
4. 它停住。开不问、写规格、改文件，都不是它的输出。你再决定要不要敲它点名的下一条。

术语。路由，就是按你的处境指出下一站，而不是把活干完。上下文，是这一次对话里模型还能看见的那些文字。清空，是把这些文字整个去掉。压缩，是把它们挤短之后带进下一次。阶段边界，是一段工作结束、下一段还没开始的那个缝；作者认为「这段上下文怎么处理」只该在这个缝上问。这些是我用普通话给说明页里的词做的定义。

容易混淆的一点：`ask-matt` 和 `grill-with-docs`。前者只点名。后者才开始追问，并且会把定下来的词写进仓库里的词汇表。你若已经知道要追问，就不要再问路由器。说明页写的正是这种情况：你已经选好了技能，它就没有用处，直接调用那一项。

什么时候不用。第一，技能已经选定。第二，你想让它路由你自己写的、或不在这套目录里的技能。它不做这件事。第三，你其实想让它开始改代码。那不是它的输出，硬让它做，就偏离了作者写明的停止。

客户端的写法要分开。Claude Code 用的是斜杠：官方说明页写的调用就是输入 `/ask-matt`。Codex 在仓库 README 里的安装是另一组命令，先 `codex plugin marketplace add mattpocock/skills`，再 `codex plugin add mattpocock-skills@mattpocock`。说明页没有另外写出一套 Codex 选择器的点选步骤。所以下面的示例只演示已经写明的斜杠，不把某种我没有在这页上看到的选择器说法，写成官方命令。安装命令来自 README 的安装节，不是本课要你现在去执行的步骤。

<details>
  <summary>路线有哪几类，以及两个作者已经写明的故障</summary>
  <p>说明页把路线分成几类，而不是一张对所有情况都正确的清单。主路是从想法到交付：追问、规格、票据、实现、复查，然后回顾。它有分叉。一个分叉是先做原型，因为有的问题要看到能跑的东西才能定。另一个分叉是规格加票据，只在工作跨过一次会话时才值得。上匝道用来接入别人交来的故障、已经坏了的东西，或大到一次会话装不下的事。代码库健康是维护，不是做功能。单独使用的技能不在这些链上。底下还有一层专门管用词的参考技能。</p>
  <p>阶段边界上，说明页给出一个有顺序的选择，不是一张平铺的菜单。先排除「继续」，因为只有继续能让这次会话仍然是第一手材料。往后才是清空、交接、子代理，压缩放在最后，因为前面几样更便宜或更精确。作者认为，交接常被误当成「换一个上下文的通用办法」，其实它给的只是可携带性。</p>
  <p>说明页还写了两个尚未修好的问题。一个是：很多技能故意不让模型自己调用，于是代理从它看见的技能名单里找不到它们，就报告「没安装」。作者的说法是它们已经安装，直接敲斜杠，或去查 Claude Code 插件的清单文件。另一个是：路由器有时按自己的一行摘要描述别的技能，并不打开那份技能文件。说明页举的后果包括，只凭摘要就建议跳过 to-spec，后来票据把工作量算少了。因此，凡是你准备照做的、关于另一项技能的说法，先让它打开那份 SKILL.md。</p>
</details>

## 示例
{: #example}

贯穿场景是一台 ESP32 充电桩固件。你懂 OCPP 1.6：桩要用 StatusNotification 上报状态。你不懂这些技能。眼下的卡点不是不会写 GPIO，而是「打开」还没有定义。它可能指接触器吸合，也可能指连接器锁止。这两个词若不定下来，代理会按它猜的那个去改引脚。

不用 ask-matt 时，你会把整句话扔给代理：「帮我在继电器打开时发送 StatusNotification。」代理分不清你要定义词，还是要改固件，于是直接改代码。这就是这一课要挡住的地方。

环境和前提：一个已经有固件仓库的目录，技能按作者的安装说明装好。本示例不要求你现在安装。你在对话里操作，不在桩上操作。下面全部是模拟，不是在你的机器上、也不是在 WSL 里实测过的记录。

在哪里操作：Claude Code 的对话输入框。怎么调用：输入斜杠 `/ask-matt`，然后把下面这段粘贴进去。Codex 的官方安装命令见上一节；本页没有给出选择器里要点哪一项，所以这里不演示点选。

粘贴的输入：

<pre class="echo"><code>I am in an ESP32 firmware repo for an OCPP 1.6 charger.
I want a StatusNotification when the relay opens, but I have not decided whether "open" means the contactor or the connector lock.
Which skill should I type next, and where do I stop?
Do not edit files.</code></pre>

按说明页上的地图，这个处境是：人在一个工作目录里，计划还模糊，问题有可能在一次会话里谈清。地图会把下一站指到 `/grill-with-docs`，而不是指到「不在工作目录时用的追问」，也不是指到实现。它还应该告诉你：词由你来定，它自己停住。

模拟回显，不是实测：

<pre class="echo"><code>Next: type /grill-with-docs.
You are in a repo, and this word can be settled in one session, so not /grill-me and not /implement.
You decide what "open" means. I stop here. I will not open or edit files.</code></pre>

<p class="stop">停在这里。不要让它修改源文件，不要让它写 platformio.ini，不要编译，不要给充电桩刷写，也不要连接桩的串口。那些是写入和设备操作。本课的过关不需要它们发生。</p>

会看到什么：一段指出下一条命令的文字，以及一句它自己停住、不改文件。你接着可以自己敲 `/grill-with-docs`。那是下一课的事，这一课不跑它。

常见出错：代理没有停，而是说「我先改 main.cpp」。另一个常见出错，是它声称 grill-with-docs 没安装，因为它从注入的名单里看不见这项技能。说明页把这写成已知问题：名单不完整，不代表文件不在。处理是仍可敲斜杠，或核对插件清单；不要顺着它改去一条更短的路线。若它描述另一项技能会做什么，而你准备照做，先让它打开那份 SKILL.md。作者写明，技能文件和路由器冲突时，以技能文件为准。

自检：看工作区有没有新的改动。没有，才算停住了。

过关标准：你能复述「它只点名下一条命令，然后停」。你能指出这次为什么不是直接实现。仓库里没有被这次问答改动的文件。你还没有给桩上电，也没有刷写。
